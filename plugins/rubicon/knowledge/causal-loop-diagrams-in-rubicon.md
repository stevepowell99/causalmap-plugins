# Causal loop diagrams in Rubicon

Rubicon codes a causal loop diagram as causal links between positively named variables, each with a plus or minus, finds the loops the combined links make as a tabulate step, gives each loop's polarity as reinforcing or balancing, and counts both the documents that tell a loop whole and the documents behind each of its links, so a judgement about sustainability, stalled results or widening gaps rests on recounted loops.

Back to [causal loop diagrams](causal-loop-diagrams.md), which covers the method and how loops answer evaluation questions. The coding, filtering and drawing on [causal mapping in Rubicon](causal-mapping-in-rubicon.md) hold here too, with one difference: the factors are variables, so combining opposites does not apply.

## As a plan

**Code.** A causal coding over a closed list of variables: either an agreed list, or the respondents' own labels grouped into a list of variables and the documents read again against it, the two closed routes on the causal mapping page. An open coding alone finds almost no loops, because a loop closes only where the same variable is recognised at both ends. Each variable is named in its positive form ("Household income", never "Income fell" or "Poverty"), and its `means` says what counts as a change in it either way. The code step has three columns, cause, effect and `sign`, the last nominal with the values `plus`, `minus` and `unclear`, and names them as its `links` (`{"from": "cause", "to": "effect", "sign": "sign"}`). The coding instruction says how to read a sign (plus where the two move the same way in the source's account, minus where they move opposite ways, unclear where the source does not say), to code a source's "less X" against X with the sign carrying the direction, and to look in each narrative for a link back from an effect to an earlier cause, coding it wherever the source states it.

**Tabulate the map.** A tabulate step by cause, effect and sign, with `sparse` set, gives each signed link that occurs its cell, the documents behind it, exactly as a causal map's links are counted. A link that some sources give as plus and others as minus has two cells.

**Tabulate loops.** A tabulate step over the same code step, counting by cause and effect, with `loops` set, combines every document's links and finds every loop in them of up to `loop_links` links (four by default, at most six), each loop visiting no variable twice; `through` keeps only the loops through the variables it names, such as the outcome. A link some sources give as plus and others as minus counts as two links, so one cycle of variables can appear once as reinforcing and once as balancing. The table counts by four columns. `loop` is the loop's variables in order, from the one first alphabetically, each followed by its link's sign (`income →+ reinvestment →+ income`). `polarity` is `R` where the loop has an even number of minus links, `B` where odd, `unknown` where any link is unclear. `part` says what a cell counts: `whole`, the documents whose own links make all of the loop, which may be none; `link`, the documents behind one of its links, named in the fourth column, `link`; and `driver`, the documents behind a link into the loop from a variable outside it, such as the programme. Each loop has a marker, R1, R2, B1, numbered by polarity in the table's order, which the answer and the report's diagrams both use. Every cell's rows are the passages behind it.

**Filters.** Any of Causal Map's link filters can come first, in the filter-ordering rules' order, to narrow what loops are sought in: tracing from or to the outcome, keeping one group of documents, zooming hierarchical variable names. Combine opposites is left out, since a variable has no opposite. Frequency filters thin out the links loops are made of, so a loop step seldom sets one.

**Judge.** Loop cells are counts like any other, so a judge step's rules can be written on them before any reading. For sustainability, a loop table with `through` naming the outcome, and a rule picking `{"polarity": "R", "part": "whole"}`, with levels such as "likely to last where at least three documents tell a reinforcing loop through the outcome"; a second criterion on `{"polarity": "B", "part": "whole"}` for the loops that erode it; and, where it matters whether a loop runs on the programme's money, a reading criterion that weighs each loop's links and drivers against the evaluator's description of what counts as funded. Whether a loop linked up from separate accounts counts, at what least-told link, is the evaluator's call, made in the rubric before the coding, as for any judge step.

**Write.** Each loop the answer relies on, named by its marker and its variables in order, with its count of documents telling it whole and the count of its least-told link, each citing its cell; a loop nobody told whole is described as linked up from separate accounts; nothing about which loop wins, how fast, or by how much.

**Draw.** A `{{figure}}` line naming a loop table draws one small diagram per loop the answer cites, up to six, as a circle of variables with plus or minus at each arrowhead and the loop's marker in its centre, with the links into it from outside drawn in from beyond the circle in dashed boxes; each arrow opens the passages behind it. A `{{figure}}` line naming a table by cause, effect and sign draws the whole signed map, which keeps the links that sit in no loop.

Where variables or links are agreed, people agree them, and a workflow cannot stand in for that. Loops, those nobody told whole above all, are a draft to make sense of with the people who live in the system before they become a finding; a run can stop once the loops are found, so the evaluator can take them to stakeholders before the answer is written.

Where part of a question is outside this, the workflow says so under `cannot_answer`: which loop dominates and how the system will behave over time need a simulation model, which documents do not support; how strong or fast a loop is cannot be read from accounts; and a question about one high-stakes loop in one place is better served by [process tracing](process-tracing.md).
