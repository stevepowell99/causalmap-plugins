# Rubicon for Claude

**Rubicon: checkable AI for evaluators.**

Rubicon answers an evaluator's questions from a folder of documents, such as interview transcripts, inside your own Claude. It settles the questions with you, then answers them through a workflow of as many steps as they need, such as coding the passages on each part of the question, comparing groups or judging the counts against a rubric, and leaves that workflow for fixed rules to carry out again, so every count in the answer is made by fixed rules from the coded passages and every quotation is checked against its document. The model calls run on your own Claude plan; nothing is sent to Causal Map.

## Install

In the Claude app: Customize > Plugins > Add > Add marketplace, enter `stevepowell99/causalmap-plugins`, then install Rubicon from it. In a terminal: `/plugin marketplace add stevepowell99/causalmap-plugins`, then `/plugin install rubicon@causalmap`; `claude plugin marketplace update causalmap` followed by `claude plugin update rubicon@causalmap` fetches a new version there.

It needs Python 3.9 or later and Node.js, and installs nothing else: it keeps and checks each run with the scripts in its own `engine/` folder, written in Python's standard library. If Python or Node.js is missing, `/rubicon` says so and offers to install it.

## Use

Open the folder holding your documents in Claude's Code tab or in Cowork, or attach the documents to a chat, and type `/rubicon` followed by your question. Rubicon lists the documents it found and asks you to confirm them, then settles the question with you before it starts. Each run gets a folder of its own beside `corpus/`, which lists the documents and the facts about them; documents added to the folder later are offered for the corpus at the next question, and each run's folder keeps the corpus as it answered from it. In it Rubicon writes three files named from the question and the date: the report (`.html`), where every number and quotation opens what it rests on; the same report for Word (`.doc`); and the whole run in one file (`.zip`), to keep or pass on; it holds your documents, so share it only with people allowed to read them. Where the documents were attached rather than in a folder you opened, the three are handed back where the app puts files for you. The plain answer is `recount/answer.resolved.md`, `work/` holds the audit trail, and `workflow.json` with `coded/` the workflow behind every count.

## What it runs, writes and sends

- **Runs** the Python and Node.js scripts in its own `engine/` folder on your computer, or in the workspace Claude provides, to convert documents to text, recount, check quotations, draw maps and write the report. They use the standard library only and make no network requests. If Python or Node.js is missing, it offers to install them with your system's package manager (winget, Homebrew or apt), and does so only after you agree.
- **Writes** only in the folder holding your documents (or a folder it makes for documents attached to a chat), where each run gets a folder of its own; in the app's outputs folder, where it copies the report for you; and in the plugin's data folder, where it keeps a list of the folders it has answered questions from and of where each run's folder is (paths only), so it can list your earlier runs.
- **Sends** your documents only to Claude, under your own Claude plan, as anything you share with Claude is. Nothing goes to Causal Map or anyone else. Beside each table of causal links, a report offers a workbook in the layout Causal Map's Import XLSX reads, holding those links and the full text of the documents they come from; the browser makes it from what the report already holds and saves it to your computer, and it reaches Causal Map only if you import it there yourself. On a free Causal Map plan an imported project is public. A report carries its two typefaces (Libre Franklin and Newsreader, SIL Open Font Licence 1.1) and, where it has a map, Graphviz (Viz.js 3.31.0, MIT, with Graphviz under the Eclipse Public Licence 2.0 and Expat under MIT) inside the one file, so opening it on a network that reaches nothing looks and draws the same; the licences are in the engine's `vendor/` folder.
- **Reads** only the folder holding your documents, a folder you ask it to search for earlier runs, its own files and its data folder. Nothing else on your computer or from the session it runs in is read.
- **Checks the published version.** At the end of a run, once the report is handed over, Claude says in one line that it is checking and that you can deny it, then checks the published version on GitHub with its own web fetch tool, reading Rubicon's `plugin.json` from `raw.githubusercontent.com`, which tells GitHub that a copy was fetched and sends it nothing else. If the published version differs from yours, Claude says so in one line with the steps to update. Claude asks your permission for the fetch as for any other; if you deny it, nothing more is said about versions.
- **Asks Claude to start helpers** where a run has a second reading: a second coder and a checker, which read the same documents in the same session.
- **Contacts no other address.** A report loads nothing from the internet. Its closing paragraph links to `causalmap.app` and to Causal Map's LinkedIn page, which open only if the reader clicks them. The scripts contact no address.

The files in `engine/rubicon_open/cm/` are copies of Causal Map's own filter code, which is pure: it reads the coded links it is given and returns filtered links, with no files, network or browser.
